# Проверка готовности MoneyGraph AI

Дата: 23 сентября 2026. Проверенный коммит: `3e44b6d`.

Вывод: аналитический движок выполняет обязательные требования к расчётам и выгрузкам. Интерфейс пока не готов к приёмке: схема может менять направление переводов, теряет связи и части выбранной сети. Зелёные Python-тесты и успешная сборка frontend не доказывают корректность графа в браузере.

Проверка выполнена без правок исходного кода. Создан только этот отчёт; установлены зависимости frontend для сборки. Прогоны и сборка выполнены во временных каталогах. Проверочная копия интерфейса использует текущий `output/graph.json`, исходные публичные данные не перезаписывались.

## Исправить до сдачи

### 1. Критично: граф переворачивает переводы

Источник: `frontend/src/App.jsx:359–375`. Рёбра индексируются как неориентированные пары, затем реальные концы заменяются на родителя и ребёнка дерева.

Воспроизведение на официальных данных: узел `100000000041368100` — terminal с нулём исходящих. Реальная связь `100000003684369100 → 100000000041368100` на 160 000 KZT рисуется в обратную сторону.

Исправление: алгоритм размещения определяет координаты. Направления, суммы и количество переводов нужно брать из исходных рёбер. Встречные переводы должны оставаться двумя отдельными связями.

Приёмка: для каждого нарисованного ребра существует исходное ребро с такими же source, target, sum_kzt, n_tx.

### 2. Критично: дерево теряет выбранные узлы, циклы и перекрёстные связи

Источник: `frontend/src/App.jsx:301–303,367–379`. Узлы вне обхода от единственного корня удаляются; остаются только рёбра дерева.

На официальном top-30 отображаются 13 узлов и 12 связей, шесть стрелок направлены неверно. Между этими 13 узлами реально есть 14 связей. При выборе boundary из первых 48 выбранных boundary остаётся один.

Исправление: показывать все компоненты выбранного подграфа и все реальные связи между оставленными узлами. Лимит узлов допустим, но должен быть явным и не должен превращать финансовую сеть в вымышленную иерархию.

### 3. Режим кластеров сбрасывается в Hunt

Источник: `frontend/src/App.jsx:837–844,683–688`; аналогичный вызов при смене кластера около строки 930. После `setMode('cluster')` вызывается `reRootTree`, который устанавливает `hunt`.

Исправление: разделить выбор корня и выбор режима. Приёмка: вкладка кластеров остаётся активной, выбор сообщества показывает его узлы и гипотезу, в том числе при повторном переключении.

### 4. Поиск и раскрытие соседей не гарантируют видимость связей

Источники: `frontend/src/App.jsx:244–270,353–356,653–676,738–754`.

- У top-1 `100000000331309100` пять плательщиков и 99 получателей. На стартовой схеме видны 79 получателей и ни одного плательщика: исходящие первыми исчерпывают лимит. Индикатор скрытых соседей у корня этого не сообщает.
- При фильтре колена 4 поиск этого узла с глубиной 2 даёт один узел без связей. Поиск сбрасывает фильтр роли, но сохраняет колено и seed.
- Клик по скрытому контрагенту меняет карточку, но не добавляет выбранный узел на граф.

Исправление: выделять место и входящим, и исходящим; показывать полный счётчик скрытых соседей; после поиска либо сбрасывать ограничивающие фильтры, либо явно объяснять ограничения; переход по контрагенту должен делать его видимым.

### 5. Реестр и история показывают отсутствие данных как нулевые переводы

Источники: `analytics/export.py:180`, `frontend/src/graphAdapter.js:64`, `frontend/src/LedgerPage.jsx:73`, `frontend/src/App.jsx:1187`.

Официальный JSON не содержит transactions/timeseries. Адаптер превращает отсутствие в пустой массив, реестр считает суммы только по нему. Поэтому у всех клиентов получаются 0 KZT / 0 переводов, хотя карточка по агрегатам показывает ненулевые потоки. В браузере у top-1 одновременно показаны 23 млн исходящих и «0 tx».

Варианты: подключить реальные транзакции либо до этого убрать историю и реестр из основного сценария. Если реестр остаётся, суммы брать из рассчитанных метрик, а отсутствие детализации подписывать «Детальные операции не загружены». Отсутствие экспорта transactions само по себе не нарушает обязательный минимум ТЗ.

### 6. В поставке одновременно находятся старые и новые результаты

Источник: `frontend/scripts/sync-engine-data.mjs:7–13`.

Текущий `output/` содержит 91 кластер, 444 boundary и top-1 `100000000331309100`. Закоммиченные `frontend/public/data/` содержат старые результаты: 87 кластеров, без boundary и другой top-1. В старом JSON отличаются 1 343 роли и все приоритеты; в старых CSV 509 evidence без чисел.

Штатный `npm run dev/build` обновляет JSON, но не три CSV. Прямой Vite или fallback при отсутствии output может показать старую аналитику. `output/` сейчас не добавлен в git.

Исправление: выбрать один официальный источник, синхронизировать полный комплект результатов либо убрать старые публичные CSV. Упаковать свежие три CSV для сдачи. Старый `pipeline.py` обозначить и отделить как архив, сохранив одну основную команду `run_pipeline.py`.

## Что переделать в самой сетке

1. Сохранить три зоны: компактные фильтры слева, граф в центре, карточка справа.
2. Объединить Network и Hunt в «Окрестность»: они используют одинаковую ветку построения. Основные режимы — «Окрестность / Топ-30 / Кластеры».
3. Перенести длинный рейтинг из нижней части карточки в отдельную полноценную таблицу Top-30 с причинами приоритета. На экране графа оставить выбранный узел и его объяснение.
4. Заменить «Вся сеть / полный срез» на «Все роли» или честное описание отображаемого подграфа. Показывать «80 из 257 узлов окрестности», если действует лимит.
5. Подбирать масштаб по ширине и высоте графа, добавить «Вместить граф». Сейчас камера учитывает только высоту (`App.jsx:586`); размещение крупного distributor растягивается на 7 176 px. В браузере большая часть связей уходит за края, сверху остаётся много пустого места.
6. Использовать единый русский язык: «Окрестность», «Приоритеты», «Плательщики» вместо Hunt, Priority ranking и in°.
7. Изменить категоричные «Организаторы», «управление схемой», «деньги оседают» на «Признаки координации», «Наблюдаемое удержание». Источник: `frontend/src/i18n.js:27–48`. ТЗ требует гипотезы, а не утверждения о виновности или полном банковском балансе.
8. Историю и ассистента оставить дополнительными действиями после исправления главного сценария.

## Остальные замечания

- `docs/DEMO_SCRIPT.md:38–40`: демонстрационный консолидатор `100000005382566100` сейчас находится в кластере 19. Сценарий указывает 20; текущий кластер 20 содержит 25 узлов и 0 seed. Перегенерировать демо-таблицу после изменений алгоритма.
- `backend/main.py:32`: при документированном `MONEYGRAPH_GRAPH_JSON=output/graph.json` health возвращает 500 из-за `relative_to(ROOT)` для относительного пути. Default запуск работает. Нормализовать путь и безопасно выводить источник.
- `backend/copilot.py:96–126`: «Топ 5 по внешнему притоку» в режиме правил возвращает priority_score. Для неподдерживаемого критерия объяснять ограничение; численные скоры округлять.
- `analytics/evidence.py:84`: «достижимы seed-клиенты» уточнить как потоки от seed, достигающие узла за ≤2 шага. Считаются предшественники по входящим связям, а не seed ниже по потоку.
- API уже имеет карточку с пробелами данных и следующим запросом, а также устойчивость сети. Подключение первого блока в UI полезно, но это расширение, а не блокер обязательного ТЗ.

## Соответствие плану

Основные фазы движка реализованы. Часть P1/P2 не завершена: например, split_max из `docs/GRAPH_ENGINE_PLAN.md:235`; API устойчивости не выведен в UI. Они не блокируют обязательную сдачу.

React вместо первоначального статического Cytoscape допустим по ТЗ. Изменённые пороги и веса зафиксированы в README и GRAPH_DECISIONS; возвращать старые формулы ради буквального совпадения с ранним планом не требуется. Предложенные поля контракта с пометкой `[ADD]` не следует считать обещанными готовыми функциями.

Порядок завершения: достоверность направлений и сохранность графа → режимы/поиск/видимость соседей → единые данные и честные состояния отсутствия детализации → читаемость и формулировки → актуальный сценарий защиты. После исправлений повторить живой поиск произвольных coordinator, terminal, boundary и изолированного seed, проверить входящие/исходящие, кластеры и полный top-30.
