# Локальный Copilot через Ollama

Ollama запускает готовую LLM на компьютере. Ключ NVIDIA, Brev или другого провайдера не нужен. Модель выбирает функции над `GraphStore`; роли и суммы по-прежнему берутся из выгрузки. После установки Ollama и скачивания модели внешняя сеть для этого режима не требуется.

## 1. Установка

Для Windows из PowerShell:

```powershell
winget install --id Ollama.Ollama --exact --source winget --accept-package-agreements --accept-source-agreements
```

Либо установите приложение с [ollama.com/download](https://ollama.com/download). На Linux/macOS используйте инструкции для своей системы на этом сайте. После установки откройте новый терминал, чтобы команда `ollama` появилась в PATH. Стандартный путь Windows: `$env:LOCALAPPDATA\Programs\Ollama\ollama.exe`.

Приложение Ollama должно работать. Если локальный сервер не запущен, выполните `ollama serve` в отдельном терминале. Проверка: `http://127.0.0.1:11434/api/version`.

## 2. Модель

Из корня репозитория:

```sh
ollama pull qwen3:4b
ollama create moneygraph-qwen3:4b -f backend/ollama.Modelfile
```

Выбрана [Qwen3 4B](https://ollama.com/library/qwen3:4b): модель с поддержкой вызова функций и русского языка, веса Q4_K_M занимают около 2,5 ГБ. Оперативной памяти требуется больше размера весов. Локальный профиль `moneygraph-qwen3:4b` использует окно контекста 8 192 токена из `backend/ollama.Modelfile`, чтобы поместились описания функций и их результаты.

Для Ollama используется native endpoint `/api/chat`, `think=false` и строгая JSON-схема плана `{name, arguments}`. Модель выбирает одну из пяти функций; допустимые gid ограничены идентификаторами из вопроса/выделения. Если данных недостаточно, допустимо действие `clarify`, после которого приложение выдаёт подсказку или ответ по правилам. Один вопрос использует один запрос к LLM, финальный текст формирует сервер. Составные цепочки, требующие сначала получить неизвестный gid, а затем задать про него новый вопрос модели, доступны во внешнем режиме `openai` либо через несколько отдельных вопросов.

## 3. Настройки backend

Установите зависимости:

```powershell
.venv/Scripts/python -m pip install -r backend/requirements.txt
```

Если `backend/.env` ещё нет, скопируйте пример:

```powershell
if (-not (Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
```

На Linux/macOS можно скопировать файл вручную или использовать `cp -n backend/.env.example backend/.env`.

Содержимое локального профиля:

```dotenv
LLM_PROVIDER=ollama
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_MODEL=moneygraph-qwen3:4b
LLM_API_KEY=
LLM_TIMEOUT_SECONDS=60
```

`backend/.env` исключён из Git. Он загружается при старте независимо от текущей папки терминала. Переменные окружения процесса имеют приоритет над файлом, включая явно заданную пустую строку. После изменения настроек перезапустите API.

`LLM_TIMEOUT_SECONDS` — общий бюджет всего планирования одного вопроса, а не время каждого раунда отдельно. Диапазон: больше 0 и не больше 300 секунд; по умолчанию 30. В локальном примере 60 секунд оставлены для первого запуска на CPU. При превышении бюджета сервер отменяет запрос к модели и возвращает `mode="rules"` с пояснением.

## 4. Настоящая проверка модели

Проверка топа без запуска FastAPI:

```powershell
.venv/Scripts/python -m backend.check_copilot
```

Все пять функций:

```powershell
.venv/Scripts/python -m backend.check_copilot --all
```

Отдельные сценарии: `--case node`, `--case neighbors`, `--case common`, `--case path`.

Команда выбирает gid из текущей выгрузки, вызывает реальную модель и проверяет режим, ожидаемую функцию и аргументы. Она выводит время каждого вопроса. Успех обозначается `PASS ... mode=llm`. Фолбэк считается **неуспехом**, даже если его ответ выглядит правильным. Код завершения: 0 — все выбранные проверки прошли, 1 — ответ модели не прошёл проверку, 2 — настройки/данные для проверки не готовы.

Это отдельный проверочный запуск. `pytest` использует имитацию LLM и не загружает модель на каждый тест:

```powershell
.venv/Scripts/python -m pytest tests/integration/test_api.py -v
```

Проверка на Windows, Ollama 0.34.3, Qwen3 4B Q4_K_M, выполнение на CPU: все пять сценариев дали `mode=llm`; после загрузки модели в память топ — 3,9 с, карточка — 4,6 с, соседи — 5,8 с, общие получатели — 9,5 с, путь — 8,5 с. Это разовый замер на текущем ноутбуке, а не гарантия скорости на другой машине или для любого вопроса.

## 5. Запуск API и демо

```powershell
.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://localhost:8000/docs`, выберите `POST /api/ask` и выполните:

```json
{"question":"Покажи 3 узла с наибольшим priority_score.","selected_gid":null}
```

Ожидается `mode="llm"`, ответ по графу и строковые `gids`. Первый запрос может быть медленнее последующих из-за загрузки модели в память. Для демо сначала выполните проверочный запрос и оставьте Ollama запущенной.

Фронтенд использует тот же [контракт API](COPILOT_API.md), независимо от того, выбрана Ollama или внешний провайдер. Пока идёт ответ модели, панель чата должна показывать загрузку и не блокировать граф.

## 6. Если модель недоступна

- Проверьте `ollama list`: должен существовать `moneygraph-qwen3:4b`.
- Проверьте, что Ollama запущена и доступна на порту 11434.
- Посмотрите `ollama ps`: там указаны загруженная модель и устройство выполнения.
- Если ответ переходит в `rules`, запустите `backend.check_copilot` и проверьте настройки, время и выбранный моделью инструмент.
- Если локальная модель слишком медленная, можно выбрать меньшую модель или использовать другой компьютер/провайдер; повторная проверка функций обязательна.

Для полного отключения LLM задайте `LLM_PROVIDER=openai` и пустой `LLM_API_KEY`, затем перезапустите backend. Пайплайн, CSV и статический интерфейс продолжают работать независимо от модели.

## Соответствие ТЗ

AI-ассистент — дополнительная функция (§8), NVIDIA/Brev не обязательны. Локальная модель соответствует локальному запуску (§9). Обязательные CSV, роли, кластеры и приоритеты воспроизводятся без LLM. Лимит пяти минут относится к аналитическому пайплайну, а время ответа чата измеряется отдельно. Наличие Ollama не исправляет известные дефекты аналитики — см. [delivery-статус](DELIVERY_STATUS.md).
