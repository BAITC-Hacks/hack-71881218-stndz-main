# Передача и проверка MoneyGraph AI

Дата: 2026-09-23. Источники требований: [ТЗ](../context/TASK.md) и [план движка](GRAPH_ENGINE_PLAN.md). Этот файл описывает актуальный путь запуска; история архитектурных решений находится в [GRAPH_DECISIONS.md](GRAPH_DECISIONS.md).

## Один официальный источник

```text
data/*.parquet
    → python run_pipeline.py
    → output/{nodes_roles.csv, clusters.csv, top_nodes.csv, graph.json}
        → FastAPI → /api/graph, карточки, транзакции, выгрузки, устойчивость, ассистент
        → sync-data → frontend/public/data/ → локальная копия интерфейса
```

Основной запуск — `python start_dev.py`: свежий пересчёт, FastAPI и Vite с единым адресом API. Порты настраиваются через `--api-port` и `--web-port`; завершение launcher останавливает его серверы. Раздельный запуск описан в [README](../README.md).

`sync-data` переносит JSON **и три CSV**, предварительно проверяя наличие каждого исходного файла. Отсутствующий официальный артефакт останавливает запуск, поэтому старый набор не выдаётся за актуальный. Dev и preview используют одинаковый прокси `/api`.

Интерфейс сначала запрашивает API. Если сервер недоступен, явно обозначается режим локальной выгрузки; основные данные доступны из синхронизированного снимка. Для карточки с серверными рекомендациями, устойчивости и ассистента требуется API. После нового расчёта нужно перезапустить API и синхронизировать frontend; для preview дополнительно пересобрать `dist/`.

## Что входит в рабочий сценарий

Интерфейс на русском языке. Три режима схемы — **«Окрестность»** выбранного клиента (1–2 шага), **«Топ-30»** и **«Кластер»**. Фильтры по роли, колену и seed применяются к показанному срезу; рядом указано число видимых узлов и связей, скрытые узлы можно добавить. Отдельные разделы содержат все приоритеты, сообщества и полный список клиентов. История операций находится в карточке клиента и использует реальные транзакции текущего снимка.

| Действие аналитика | Источник |
|---|---|
| Найти любой GID и увидеть направленные связи | официальный граф, включая 19 изолированных узлов |
| Понять роль, приоритет и ограничения | evidence/metrics/flags и `/api/nodes/{gid}/card` |
| Просмотреть все 30 приоритетов | `rank` и `priority_score` того же расчёта |
| Исследовать кластер и его гипотезу | `clusters` официального экспорта |
| Просмотреть реальные переводы | транзакции экспорта и `/api/nodes/{gid}/transactions` |
| Скачать согласованные результаты | `/api/exports/{filename}` или синхронизированная локальная копия |
| Сравнить сеть после изъятия топ-N | `/api/resilience` |
| Получить ответ со ссылками на узлы | `/api/ask`, LLM или правила |

## Обязательные критерии и проверка

Предшествующий аудит движка выполнил 28 модульных и 97 интеграционных тестов. Два независимых расчёта заняли 5,199 и 3,214 секунды; три CSV совпали побайтно. Это базовая проверка **до изменений интерфейса и API**, не результат финального прогона текущих изменений.

Подтверждённые свойства аналитики: 2 248 строк узлов без пустых обязательных полей; 91 кластер; топ-30; 444 boundary; ни одного seed с ролью transit; все 19 изолированных узлов сохранены. Длина evidence не превышает 200 символов, GID в JSON — строки, `NaN` заменён на `null`.

На работающих серверах выполнены **22 из 22 HTTP-проверок**: напрямую через FastAPI `:8000` и через Vite `:5175`. Проверены health, граф, карточка, операции с направлениями `all`/`in`/`out` и пагинацией, три CSV, устойчивость, ассистент и ответы на неверные параметры. Скачанные CSV побайтно совпадают с `output/`. Ассистент проверен в режиме `rules`; внешний LLM-провайдер этой проверкой не подтверждён.

В браузере вручную подтверждены подключение к API, официальные счётчики сети, профиль первого клиента в топе и его реальные операции: **134 перевода**, из них 8 входящих на **984 635 ₸** и 126 исходящих на **23 001 375 ₸**. Эти числа совпали с API и экспортом. В режиме «Кластер» подтверждены интерактивный граф, выбранная карточка и полное отображение проверенного среза: **53 из 53 узлов, 59 из 59 связей**. Остальные сценарии браузерной проверки фиксируются отдельно по мере выполнения. Полная проверка мобильного интерфейса, preview и переключения в локальный режим здесь не заявлена.

Команды для повторной проверки:

```sh
python -m pytest tests -q
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
python start_dev.py
```

Затем пройти [демо-сценарий](DEMO_SCRIPT.md): произвольный GID и изолированный узел, направления переводов, карточка с evidence и ограничениями, топ-30, кластер, реальные транзакции, три скачиваемых CSV, устойчивость и ответ ассистента. Отдельно проверить preview и явно обозначенный режим при остановленном API. Факт завершения этих проверок фиксируется по реальному результату, а не по наличию компонентов в коде.

## Границы и оставшиеся решения

- Историческая альтернативная реализация `pipeline.py` удалена вместе с legacy-переключателем тестов. Все проверки выгрузок запускают официальный `run_pipeline.py`; действующие инструкции не предлагают другой движок.
- Предложения `[ADD]` в [GRAPH_DATA_CONTRACT.md](GRAPH_DATA_CONTRACT.md) и `split_max` в плане движка не являются обязательными пунктами ТЗ. Их нельзя выдавать за реализованные возможности.
- Роли — структурные гипотезы. Входящие вне выборки, межбанковские переводы, суммы ниже 5 000 KZT и исходящие четвёртого колена не наблюдаются. Изъятие узлов моделирует связность графа, а не прогнозирует поведение людей.
- Исходные `data/`, код организаторов `starter/`, пользовательские заметки и результаты аудита сохраняются. Удалены подтверждённо неиспользуемые ресурсы и прежние страницы интерфейса, шаблонные изображения и системный `.DS_Store`. В `.gitignore` добавлены только четыре генерируемых файла `output/`; `output/READINESS_AUDIT.md` остаётся доступен для сохранения в Git.
