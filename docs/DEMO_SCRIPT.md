# Сценарий демо — 5 минут

Формат ТЗ: живой прогон и разбор 2–3 узлов по существу. Жюри может назвать любой gid, поэтому сценарий держится на объяснении правил, а не на заученных узлах.

> **Демо-узлы выбраны по результату прогона, в коде их нет.** Базовая выгрузка: 2 248 узлов, 91 кластер, топ-30. **После каждого изменения в `analytics/` перепроверить таблицу демо-узлов** (команда в конце файла): роли и номера кластеров могут сдвинуться.

## Сценарий по минутам

### 0:00–0:40 · Проблема
**Экран:** схема решения.
**Говорим:** «У аналитика есть 81 стартовый клиент. Выгрузка их исходящих переводов на 4 колена — уже 2 248 клиентов и 366 млн тенге. Вручную аналитик трассирует один узел часами. Наш инструмент за секунды отвечает: кого смотреть первым и почему».

### 0:40–1:10 · Живой прогон
**Экран:** терминал → `python run_pipeline.py`.
**Говорим:** «Одна команда от сырых parquet до трёх выгрузок. Пять секунд при лимите ТЗ пять минут. Всё локально, без GPU и внешних сервисов. Каждая роль — правило с порогом из `analytics/config.py`, а не чёрный ящик».

При изменении исходных данных API нужно перезапустить, а копии frontend — синхронизировать. Для живого показа повторяется расчёт на том же наборе; новый набор не подменяется при работающем сервере.

### 1:10–2:10 · Узел 1 — координатор с внешним притоком
**Экран:** поиск `100000000331309100` → граф окрестности → карточка.
**Факты:** первое место топа, приоритет 0,99. 5 плательщиков → 99 получателей. Получено внутри выборки 0,98 млн KZT, отправлено 23 млн KZT.
**Говорим:** «Роль coordinator: правило — не меньше 5 плательщиков и не меньше 10 получателей одновременно. Узел отправил примерно в 23 раза больше, чем получил от наблюдаемых клиентов. Источник разницы в этой выборке не виден. Это повод запросить полную выписку и входящие, включая межбанковские; структурная роль не доказывает назначение счёта».
**Показать:** блок пробелов данных и следующего запроса в карточке, затем реальные входящие и исходящие операции. Карточка использует `GET /api/nodes/100000000331309100/card`, история — `GET /api/nodes/100000000331309100/transactions`.

### 2:10–3:00 · Узел 2 — консолидатор денег seed + кластер
**Экран:** поиск `100000005382566100` → карточка → кластер 19.
**Факты:** 7 плательщиков, из них 6 — seed-клиенты; кластер 19: 26 узлов, 14 из 81 seed.
**Говорим:** «Сюда сходятся переводы шести стартовых клиентов. Кластер 19 содержит 14 из 81 seed при 26 узлах. Гипотеза кластера формируется по составу ролей: признаки сбора средств нескольких seed».
**Если спросят про seed:** узел сам seed; в приоритете известные seed умножаются на 0,8, чтобы наверх поднимались новые клиенты.

### 3:00–3:40 · Ловушка данных — terminal против boundary
**Экран:** две карточки подряд.

| | `100000002645609100` | `100000005075949100` |
|---|---|---|
| Колено | 1 | 4 |
| Получено | 546,8 тыс. KZT от 4 плательщиков | 2,2 млн KZT |
| Исходящих | нет | нет |
| Роль | **terminal** | **boundary** |

**Говорим:** «Наивное правило "нет исходящих — деньги осели" записало бы оба узла в конечные получатели, а второй — в самые крупные. Но обход выгрузки остановился на 4-м колене: исходящие этого узла просто не собирались. Таких узлов 444, мы не называем их конечными — это отдельная роль boundary, и их приоритет ограничен 0,3: наверх топа они не попадают. А первый узел на 1-м колене: обход продолжался и исходящих не нашёл, поэтому вывод об удержании обоснован».

### 3:40–4:20 · Топ приоритетов и AI-ассистент
**Экран:** топ-лист → клик по первой строке; затем (опционально) чат.
**Говорим:** «Приоритет — взвешенная сумма шести понятных компонент: концентрация потоков, структура, объём, сходимость seed, внешний приток, скорость транзита. Обоснование каждой строки — в числах».
**Чат (если поднят):** «Что запросить дальше по 100000000331309100?» — ассистент отвечает карточкой: крупнейшие контрагенты, «источник 22,0 млн KZT не виден» и следующий запрос (входящие, включая межбанковские). Запасные вопросы: «топ 3 по priority_score», «кто собирает деньги с <gid> и <gid>». «Модель не считает цифры: она вызывает функции по графу, и все числа в ответе — из выгрузки. Без модели ассистент работает на правилах».

### 4:20–5:00 · Ценность
**Экран:** `output/top_nodes.csv` или таблица в UI.
**Говорим:** «Аналитик получает ранжированный список с обоснованием — перечень на углублённую проверку. Все выводы — гипотезы, а не утверждения о виновности. Три CSV можно скачать прямо из интерфейса. План масштабирования до миллиона узлов описан в README; это план, а не выполненный бенчмарк».
**Если есть 20 секунд:** открыть устойчивость, выбрать 10 узлов и выполнить расчёт `/api/resilience?n=10`. «В текущем снимке удаление топ-10 меняет число компонент с 35 до 242. Это структурный сценарий по наблюдаемому графу; решение о проверке принимает аналитик».

## Жюри называет случайный gid — как объяснить за минуту

1. Найти gid в поиске → карточка → строка evidence.
2. Назвать роль и **правило из таблицы** (README / схема): порядок проверки coordinator → distributor → consolidator → transit → terminal → boundary → peripheral, первое совпавшее побеждает.
3. Показать числа карточки, которые сработали в правиле.
4. Если `peripheral`: «ни одно правило не сработало: например, 1 плательщик и 1 получатель — ниже всех порогов».
5. Если seed: «входящие неполные, поэтому роль transit к seed не применяется».

## Вероятные вопросы

| Вопрос | Ответ |
|---|---|
| Почему пороги именно такие? | Откалиброваны по распределениям данных: ≥ 5 плательщиков — топ-2% узлов, ≥ 10 получателей — топ-3%; решения и замеры — `docs/GRAPH_DECISIONS.md` |
| Как проверить, что нет хардкода? | gid в коде нет; тесты `tests/` запускают пайплайн с нуля на сырых parquet |
| Нет разметки — как оценить качество? | ТЗ оценивает обоснованность; каждое правило — формула с порогом, каждую роль можно пересчитать руками по карточке |
| Почему кластеризация без направления? | Louvain работает на неориентированной проекции; направление денег учитывается в ролях. `seed = 42` — воспроизводимый результат |
| Что при миллионе узлов? | Раздел «Масштабирование» README: приближённый betweenness, Leiden/igraph, визуализация только окрестностей |
| Не утечка ли данных в LLM? | Модель может работать локально; ассистент опционален, пайплайн от него не зависит |
